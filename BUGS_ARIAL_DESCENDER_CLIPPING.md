# Bug: Обрезание нижних выступов букв (descenders) при сохранении результата — Arial

## Статус
**ИСПРАВЛЕНО И ВНЕДРЕНО (2026-09-01).** Описанное здесь исследование осталось актуальным; внедрение находится в `ui/scene_textlayout.py` (см. разделы «Внедрённое изменение» ниже). Дата первоначального исследования: 2026-09-01.

---

## Описание задачи / требований

**Симптом**: При использовании шрифта **Arial** нижние выступы букв (`g`, `y`, `p`, `q`, `j`, а также кириллических `у`, `р` — выносные элементы ниже базовой линии) у **нижней (последней) строки** текстового блока **обрезаются** при сохранении изображения в папку `result` проекта.

ч**Ключевой факт от пользователя**: В редакторе (в сцене QGraphicsView) текст отображается **нормально**. Обрезание происходит **только при сохранении** (при рендере финального изображения).

**Ожидаемое поведение**: Нижние выступы букв последней строки должны полностью попадать в результирующее изображение (как они видны в редакторе).

### Корневая причина
**Опорная строка `'木fg'` не содержит букв с глубокими нижними выступами.** Для Arial:
- tight-дно опорной строки `'木fg'` = `+4.22` (18pt), определяется буквой `f` = `+0.47` и `京` = `+2.38`).
- Реальные нижние выступы глубже:
  - Латинские: `g`=+5.78, `y`/`p`/`q`=+5.5, `j`=+5.23.
  - Кириллические: `у`/`р`=+5.5.
- Даже **полный** `descent` (`+5.09`) и **`boundingRect`-дно** (`+5.094`) **глубже**, чем tight-дно опорной строки (`+4.22`).

Из-за этого `shrink_height`/`block_ideal_height` (и производная геометрия блока) **резервируют меньше нижнего пространства**, чем требуется буквам с глубокими выносными элементами. В редакторе (где элемент рисуется через трансформацию канваса QGraphicsView с antialiasing) нижние выступы отрисовываются **за пределами** зарезервированной области (и не клипаются благодаря transform view). При экспорте (`render()` в `QImage` 1:1) финальный клип по `boundingRect()`/геометрии **срезает** эти выступы у последней строки.



Дополнительно: ряд `'木fg'` содержит хвост (`д`,`ц`,`щ` =+3.98), но они всё равно **мельче**, чем `g`/`y`/`у` (. Проект фокусируется на CJK + минимальных латинских выносных, что ВЕРНО для CJK-комиксов, но НЕ достаточно для Latin/Cyrillic шрифтов.

## Внедрённое изменение (ui/scene_textlayout.py)

**Проблема с наивным probe**: использование сводной строки `'木fgурgypqj'` для `tightBoundingRect()` давало **ложный** результат (bottom = 4.219 как у базовой строки, несмотря на `'g'`=5.781). Это связано с CJK-fallback в Qt — tight-метрика смешанной строки обрезается до первого шрифтового участка. Поэтому реализован **посимвольный** расчёт.

**Реализация**:
1. Константа `_DESCENDER_BASE_STR = '木fg'` — опорная строка (без изменений базовой метрики).
2. Множество `_DESCENDER_CHARS = frozenset('gypqjyур')` — латинские (`g/y/p/q/j`) и кириллические (`у/р`) глифы с глубоким нижним выступом.
3. Функция `_descender_gap(text, ffamily, size, weight, italic)`:
   - Для каждого символа текста из `_DESCENDER_CHARS` берёт `tightBoundingRect().bottom()`.
   - Возвращает `max(0, max_bottom - base_bottom)` — избыточную глубину ниже дна опорной строки.
4. В `HorizontalTextDocumentLayout.layoutBlock()` сохранён `last_font` (шрифт последней строки с максимальным кеглем).
5. После `tl.endLayout()`, для **последнего блока документа** (`is_last_block`), вычисляется `desc_gap` по фактическому тексту блока (`blk_text`) и добавляется в `self.shrink_height` и локальный `text_padding`.

**Почему это не раздувает CJK-блоки**: `_descender_gap` возвращает >0 только если в тексте есть латинские/кириллические буквы с глубокими descenders. Для чистого CJK (`木木木`, `你好世界`) gap=0.0 на Arial/SimSun/YaHei.
